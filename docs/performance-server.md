# Серверные настройки производительности

`scripts/configure-performance.py` дополняет установку оптимизированных файлов сайта.
Он меняет только `/etc/nginx/sites-available/urbaso.ru.conf` и
`/etc/nginx/sites-available/site.urbaso.ru.conf`. Git, HTML, изображения, другие
домены, глобальный nginx, сертификаты и Docker не изменяются.

## Изменения

- gzip для HTML, CSS, JavaScript, JSON, XML, SVG и обычного текста. WOFF2, WebP и
  другие уже сжатые бинарные файлы повторно не сжимаются.
- Годовой `Cache-Control: public, max-age=31536000, immutable` только для
  `/assets/optimized/…-<12 шестнадцатеричных символов>.webp|avif|woff2|css|js`.
  Эти 12 символов — начало SHA256 содержимого. Изменение байтов требует нового
  имени файла. Установщик проверяет соответствие этих имён содержимому.
- HTML и ресурсы со старыми невариантными именами сохраняют `no-cache`.
  Ответы 404 не получают `immutable`.
- Все правила доступа, HTTPS, редиректы и доступ к инструменту проверки сохраняются.

## Установка

Сначала установить подготовленный код по `docs/performance-release.md`
(либо обычным процессом из `docs/deployment.md`), сохранив изменение
со счётчиком Метрики 33578164 в Git.
Серверный скрипт требует чистых отслеживаемых файлов и точного текущего SHA.
Неизвестные файлы не удаляются и не перезаписываются.

Скопировать `scripts/configure-performance.py` из **того же установленного
коммита** во временный каталог вне webroot. Затем выполнить от root:

```bash
python3 /ВРЕМЕННЫЙ_КАТАЛОГ/configure-performance.py ПОЛНЫЙ_ТЕКУЩИЙ_SHA --check-only
python3 /ВРЕМЕННЫЙ_КАТАЛОГ/configure-performance.py ПОЛНЫЙ_ТЕКУЩИЙ_SHA
```

Это шаблон инструкции: при подготовке команды установки заменить путь и SHA
проверенными конкретными значениями. Скрипт не выбирает ветку и не делает коммитов.

Перед записью проверяются сервер, Git SHA, активный nginx, оба симлинка vhost,
полное совпадение директив с результатом `cutover-domains.sh` и снимок всех
остальных активных конфигов. Отличия только в комментариях и пробелах допускаются;
при иных изменениях скрипт останавливается. Глобальные gzip-настройки могут
наследоваться: локальные директивы их переопределяют только в двух TLS-vhost.
Если включаемый TLS-файл уже содержит gzip-директивы, требуется ручная сверка.

Блокировки общие с доменным переключением и публикацией сайта. Резервная копия
сохраняется в `/root/backups/site.urbaso.ru/performance-…`, доступна только root
и содержит исходные конфиги, метаданные, их SHA256 и автономный скрипт отката.
Перед каждым изменением повторно проверяется, что конфиг не изменился.

После записи выполняются `nginx -t`, reload и HTTP-проверки через loopback с
настоящим TLS-именем: HTML и CSS совпадают с файлами сайта, gzip включён,
Cache-Control корректен, служебные пути закрыты, редиректы сохранены. При ошибке
исходные nginx-конфиги восстанавливаются автоматически, если не обнаружены
посторонние изменения. Более поздние изменения блокируют автоматическую замену.

## Откат

Точную команду скрипт печатает **до изменения nginx**:

```bash
python3 /root/backups/site.urbaso.ru/performance-…/configure-performance.py --rollback /root/backups/site.urbaso.ru/performance-…
```

Она проверяет пути, контрольные суммы резервной копии и текущих конфигов,
восстанавливает два исходных файла, выполняет `nginx -t` и reload. Если проверка
или reload не пройдены, возвращает конфиги, бывшие на диске перед попыткой отката.

Откат nginx и откат версии сайта независимы. Для автономного performance-релиза
код возвращается командой `install-performance-release.py rollback` из его
резервной копии; точная команда напечатана установщиком. Для обычной публикации
используется `rollback-review.sh` из соответствующей резервной копии. Старые
нехешированные файлы не получают долгого кеша, поэтому прежняя версия сайта
работает и до отката nginx. Git не хранит конфиги `/etc/nginx`: для них нужна
отдельная резервная копия, которую создаёт этот скрипт.

## Проверка результата

После успешной установки проверить сайт на телефоне и компьютере, просмотр
документов, переключение вкладок, контакты и один счётчик Метрики. Затем выполнить
повторные PageSpeed-прогоны для обоих устройств. Проверка скрипта на временных
конфигах не заменяет `nginx -t` и HTTP-проверки на действующем VPS.
