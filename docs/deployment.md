# Установка и откат

Репозиторий: `urbatron/site-urbaso`, основная ветка — `main`.
VPS: `80.93.52.205:22`, каталог сайта — `/opt/legacy-stack/sites/sweb/site.urbaso.ru/public_html`.
Публичный адрес: <https://site.urbaso.ru/>. Пользователь выполняет команды публикации сам.

## Порядок работы

1. Пользователь загружает подготовленные изображения и сообщает пути. Агент сразу получает эти файлы, проверяет их и добавляет используемые изображения в Git без перекодирования.
2. Агент сверяет доступную опубликованную версию с согласованным коммитом, создаёт ветку `codex/...`, вносит изменения и проверяет результат. Незакоммиченные серверные изменения требуют отдельного разбора.
3. Агент коммитит и отправляет рабочую ветку, передаёт один блок установки с точными SHA. `scripts/deploy-review.sh` нужно запускать из временного каталога вне webroot, получив его из этого же целевого коммита.
4. Пользователь запускает команду на VPS и проверяет сайт. Исправления публикуются тем же способом из рабочей ветки.
5. Только после приёмки агент выполняет согласованное слияние в `main` и удаление завершённой рабочей ветки. На VPS отдельно переключают сайт на подтверждённый `main`; установочный скрипт сам ничего не отправляет в GitHub.

## Установка

Интерфейс скрипта:

```bash
bash /путь/вне/webroot/deploy-review.sh codex/имя-ветки ПОЛНЫЙ_ЦЕЛЕВОЙ_SHA ПОЛНЫЙ_ТЕКУЩИЙ_SHA
```

Скрипт проверяет репозиторий, текущую ветку и SHA, отсутствие изменений отслеживаемых файлов, точную удалённую ветку и fast-forward. Перед переключением он обнаруживает входящие файлы, которые уже лежат на сервере вне Git, включая игнорируемые. Переносит их в небольшую резервную копию только при совпадении байтов с целевым Git blob. Любое различие останавливает установку; остальные файлы остаются на месте.

В `/root/backups/site.urbaso.ru/review-…` сохраняются сведения о предыдущей версии, конфликтовавшие файлы и автономный скрипт отката. Чистые отслеживаемые файлы восстанавливаются из Git, поэтому полная копия сайта при каждой правке не создаётся. Старые резервные копии автоматически не удаляются.

После переключения проверяются SHA, чистота отслеживаемых файлов, сохранность перенесённых изображений и совпадение публичного `index.html` с установленным. Функциональную проверку интерфейса агент выполняет отдельно. Если HTTP-проверка не пройдена, сайт уже может быть обновлён: сообщение содержит точную команду отката.

Для Git используется уже установленный на VPS ключ `/root/.ssh/id_ed25519_site_urbaso_repo`. Проверка ключа хоста SSH обязательна; скрипт не принимает неизвестные ключи автоматически. Секреты и приватные ключи в чат и Git не передавать.

Для изолированной проверки скрипта на временном локальном репозитории можно переопределить `SITE_ROOT`, `BACKUP_ROOT`, `SITE_URL` и `DEPLOY_KEY` через окружение. На VPS используются приведённые выше значения по умолчанию. Каталог резервных копий обязан находиться вне webroot; для тестового HTTP-сервера указывается адрес localhost. Эти переменные не добавляются в конфигурацию репозитория и не меняют параметры сервера.

## Откат

Команда печатается после установки и при ошибке после создания резервной копии:

```bash
bash /root/backups/site.urbaso.ru/review-ДАТА-ID/rollback-review.sh /root/backups/site.urbaso.ru/review-ДАТА-ID
```

Откат допускается только с записанного целевого или предыдущего SHA и при чистых отслеживаемых файлах. Скрипт проверяет резервную копию, переключает сайт на предыдущий коммит и возвращает ранее неотслеживаемые изображения. Если прежняя ветка уже сдвинулась, создаёт отдельную ветку `rollback/...`, сохраняя новую рабочую ветку. Неизвестные файлы не удаляет. Более поздние изменения блокируют автоматический откат: сначала их нужно сохранить и разобрать.

После отката открыть сайт и проверить нужную секцию. Перед продолжением работы согласовать новую исходную ветку и SHA. Скрипты не откатывают внешние сервисы и не восстанавливают неизвестные изменения, сделанные вне этого процесса.
