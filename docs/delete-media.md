# Медиа по постоянным адресам `/delete/`

Задача: сохранить публичный URL
`https://urbaso.ru/delete/astra/video/video3.mp4` и добавить небольшие файлы
каталога в Git, оставив видео вне истории репозитория.

## Почему возник 404

Конфигурация после оптимизации разрешает главную страницу, несколько служебных
URL и ресурсы `/assets/`. Остальные адреса попадают в `location / { return 404; }`.
Поэтому наличие файла в webroot само по себе не открывает его по HTTP.

`scripts/configure-delete-media.py` добавляет отдельное правило для изображений
и видео внутри `/delete/` на двух действующих доменах. Оно расположено после
запрета скрытых файлов, не разрешает исполнение скриптов и не открывает список
каталогов. MP4 получает MIME `video/mp4`; обычная статическая выдача Nginx
обслуживает Range-запросы, необходимые для перемотки.

## Применение на VPS

Скрипт и `scripts/configure-performance.py` скачиваются из одного полного SHA
ветки `codex/delete-media-20261016` во временный каталог вне webroot. Перед
запуском сверяются SHA256 обеих копий. Пользователь выполняет команду на
`urbaserge3-vps-1`; скачанный helper не запускается как самостоятельный установщик.

Это отдельное изменение Nginx: HEAD, ветки, индекс Git, содержимое сайта и
загруженные файлы не переключаются. Скрипт допускает только известную
оптимизированную конфигурацию либо результат своей предыдущей установки.
Неизвестная конфигурация требует ручной сверки.

Прежний `configure-performance.py`, запущенный отдельно, после этой правки
остановится на новом location как на неизвестной конфигурации. Повторно
переписывать Nginx старым шаблоном нельзя: это снова закроет `/delete/`.

До записи проверяются файл ролика, активные конфигурации и `nginx -t`.
Резервная копия и автономная команда отката сохраняются вне webroot, в
`/root/backups/site.urbaso.ru/`. После reload проверяются выдача фрагмента видео
с HTTP 206, его MIME и совпадение полученных байтов с файлом на диске, а также
доступность главной страницы и запрет служебных путей. При ошибке проверки
скрипт возвращает предыдущую конфигурацию.

HTTP 206 подтверждает корректную выдачу файла, но не совместимость кодеков:
после применения нужно отдельно открыть точный публичный URL в браузере.
Если HTTP уже работает, а плеер выдаёт ошибку декодирования, сначала проверить
кодеки исходника. Сам установщик не перекодирует и не заменяет видео.

## Файлы и Git

В этом коммите зафиксированы правила хранения и структура `delete/`. Исходные
изображения пока находятся только на сервере: их добавляют следующим коммитом
после открытия доступа и сверки байтов. Наличие README не означает, что все
серверные файлы уже сохранены в Git.

Видео исключены из Git корневым `.gitignore`; серверные оригиналы требуют
отдельной резервной копии. При последующей установке коммита с изображениями
нужно безопасно принять уже существующие файлы только при точном совпадении
с Git. Не удалять исходники и не использовать `git clean`.

Прежний `deploy-review.sh` не поддерживает текущее состояние detached HEAD;
его нельзя запускать для этой задачи без отдельной адаптации. Установщик
performance-релизов, в свою очередь, блокирует совпадения с неотслеживаемыми
файлами. Установка изображений требует отдельной проверки фактического HEAD
и списка файлов, которые напечатает исправление Nginx.
