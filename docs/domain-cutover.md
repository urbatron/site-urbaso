# Основной домен и перенаправления

Согласованный сервер: `urbaserge3-vps-1`, `80.93.52.205`. Новый статический сайт остаётся в `/opt/legacy-stack/sites/sweb/site.urbaso.ru/public_html`: переносить или дублировать файлы не требуется.

## Результат переключения

| Адрес | Поведение |
| --- | --- |
| `https://urbaso.ru/` | Новый статический сайт |
| `http://urbaso.ru/`, `http(s)://www.urbaso.ru/` | 301 на HTTPS без www, с сохранением пути и параметров |
| `http(s)://sitetops.ru/`, `http(s)://www.sitetops.ru/` | 301 на главную `https://urbaso.ru/`, параметры запроса сохраняются |
| `http(s)://disiner.ru/`, `http(s)://www.disiner.ru/` | Такой же 301 на главную |
| `http(s)://prodvizheniyesaytov.ru/`, `http(s)://www.prodvizheniyesaytov.ru/` | Такой же 301 на главную |
| `https://site.urbaso.ru/` | Прежний адрес для просмотра той же версии и проверки размеров |

Пути трёх прежних сайтов не переносятся на новый одностраничный сайт. Их query-параметры, включая UTM, сохраняются. Старые внутренние URL самого `urbaso.ru` не подменяются главной: неизвестный путь возвращает 404. Отдельную карту перенаправлений можно добавить после согласования.

Каталог `/opt/legacy-stack/sites/sweb/urbaso.ru/public_html`, контейнер `legacy-urbaso` на `127.0.0.1:8084`, остальные старые сайты, Docker и базы данных не изменяются. Возврат прежнего сайта выполняется восстановлением nginx-маршрутизации.

## Точная установка

Сценарий запускает пользователь на VPS из временного файла вне webroot. Передаётся **полный SHA установленного и согласованного коммита**, в котором находятся оба сценария. Он не скачивает, не переключает и не отправляет Git-коммиты.

```bash
bash /tmp/cutover-domains.sh ПОЛНЫЙ_ТЕКУЩИЙ_SHA --check-only
bash /tmp/cutover-domains.sh ПОЛНЫЙ_ТЕКУЩИЙ_SHA
```

Первый вызов проверяет условия без изменения nginx, сертификатов и файлов сайта. Второй повторяет проверки и выполняет переключение. В пользовательском блоке команд SHA всегда заменяется точным значением, а файл сценария берётся из этого коммита. Проверка `git status` требует отсутствия изменённых и неотслеживаемых файлов: неизвестные файлы не удаляются и не добавляются автоматически.

Проверяются hostname, webroot, HEAD, необходимые команды, активный nginx, A/AAAA для всех имён, SAN и срок действия сертификатов, nginx-плагин продления, ожидаемые цели симлинков, полный состав исходных vhost и отсутствие дублирующих объявлений этих имён в других конфигах. Исходные конфиги сравниваются с конфигурацией, которую владелец прислал 04.10.2026; различия только в комментариях и форматировании допускаются. При изменении директив сценарий останавливается до записи.

Используются блокировки `/run/lock/site-urbaso-domain-cutover.lock` и существующая `.git/site-deploy.lock`. Перед первой записью проверяется, что содержимое исходных конфигов осталось тем же. Перед и после Certbot дополнительно сверяются все остальные активные nginx-конфиги.

## Какие файлы меняются

Меняются четыре существующих файла в `/etc/nginx/sites-available/`:

- `urbaso.ru.conf`;
- `site.urbaso.ru.conf`;
- `sitetops.ru.conf`;
- `disiner.ru.conf`.

Добавляется `prodvizheniyesaytov.ru.conf` и его симлинк в `sites-enabled`. Существующие симлинки сохраняются. Прежние данные сайтов и файлы репозитория сценарий не меняет.

В `/root/backups/site.urbaso.ru/domains-…` перед изменениями сохраняются только затрагиваемые исходные nginx-конфиги, их пути, владельцы, права и контрольные суммы, состояния новых файлов и автономный `rollback-domains.sh`. Каталог доступен только root. Приватные ключи и содержимое сайта в эту копию не включаются.

На обоих адресах нового сайта разрешены публичные HTML, `robots.txt`, `sitemap.xml`, favicon и статические ресурсы из `assets/`. Скрытые файлы, `.git`, инструкции, документация и сценарии установки закрыты. `tools/layout-check.html` разрешён только на `site.urbaso.ru`. Nginx не исполняет PHP. Прочие пути возвращают 404. Эти правила не меняют файлы и не мешают Git работать на сервере.

## HTTPS и продление

Существующий сертификат `/etc/letsencrypt/live/urbaso.ru/` уже покрывает `urbaso.ru`, `prodvizheniyesaytov.ru` и `www.prodvizheniyesaytov.ru`. В него добавляется `www.urbaso.ru`, все прежние имена сохраняются. Для проверки владения сначала временно включаются недостающие HTTP-vhost. Выдача выполняется через `certbot certonly --nginx --cert-name urbaso.ru --expand`; новый аккаунт не создаётся, дополнительные условия не принимаются автоматически.

Сертификаты `sitetops.ru` и `disiner.ru` используются без замены. Перенаправления размещены внутри `location /`, чтобы nginx-плагин Certbot мог добавлять точные ACME challenge location. После переключения выполняется пробное продление всех трёх сертификатов через staging (`renew --dry-run`), без случайной задержки и без установки тестовых сертификатов. Приватные ключи не выводятся.

Описание Certbot: [изменение списка доменов существующего сертификата](https://eff-certbot.readthedocs.io/en/stable/using.html#re-creating-and-updating-existing-certificates).

Новый расширенный сертификат остаётся при откате: он продолжает покрывать все прежние имена. Архив сертификатов, ключи, ACME-аккаунт и система планового продления не удаляются. Если требуется ввод данных или действия с ACME-аккаунтом, неинтерактивная выдача остановится.

## Проверка и отказ

Перед каждым reload выполняется `nginx -t`. После переключения локальные HTTPS-запросы с корректным SNI проверяют сертификаты, байты главной страницы/CSS/vCard, все редиректы с тестовым путём и query-параметрами, закрытие служебных файлов и доступность инструмента проверки на `site.urbaso.ru`. HTTPS-проверка не отключает проверку сертификата. После пробного продления проверки повторяются. Публичную доступность и интерфейс агент проверяет отдельно после получения результата установки.

После reload полная проверка повторяется при ошибке в течение 30 секунд, чтобы дождаться новых рабочих процессов nginx. Каждый запрос ограничен 20 секундами; уже начатая проверка может закончиться после этого окна ожидания. Успех требует совпадения всех байтов и всех редиректов, одного HTTP 200 недостаточно. Curl не читает пользовательский `.curlrc` и распаковывает HTTP-сжатие перед сравнением. Последний неуспешный ответ, заголовки, адрес запроса и контрольные суммы сохраняются в `http-check-cutover` или `http-check-renewal` внутри закрытой резервной копии. Если несоответствие сохраняется, выполняется прежний откат.

При ошибке теста, reload, выдачи сертификата, проверки сайта или продления запускается откат затронутых nginx-конфигов. Он разрешён только для исходного, промежуточного или конечного состояния, созданного этим сценарием. Если другой процесс изменил конфиг либо Certbot после ошибки оставил неизвестные временные изменения, автоматическая перезапись запрещена: выводится путь сохранённой копии для разбора. Скрипт не выполняет `certbot rollback` для всего сервера и не восстанавливает чужие конфиги.

## Откат

Точная команда печатается **до первой записи** и после успешного переключения:

```bash
bash /root/backups/site.urbaso.ru/domains-ID/rollback-domains.sh /root/backups/site.urbaso.ru/domains-ID
```

Откат сверяет все файлы до первой записи, восстанавливает четыре исходных конфига и удаляет только созданный этой операцией vhost `prodvizheniyesaytov.ru`. Выполняет `nginx -t` и reload. Изменённые после переключения конфиги блокируют автоматический откат. Git-коммиты, файлы сайтов и сертификаты не откатываются.

## Локальная подготовка

Без nginx и доступа к VPS можно вывести конечные шаблоны в новый временный каталог:

```bash
bash scripts/cutover-domains.sh --render /tmp/urbaso-nginx-review
```

Этот режим только создаёт файлы в указанном новом каталоге. Синтаксис Bash и встроенного Python проверяется отдельно; фактическая проверка nginx/TLS/ACME выполняется на VPS и не считается выполненной до запуска сценария.
