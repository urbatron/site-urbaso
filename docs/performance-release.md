# Автономная установка оптимизации и откат

Проверенный performance-релиз скачивается из GitHub отдельным bootstrap-скриптом.
Затем локальный установщик применяет подготовленный Git bundle. Сам установщик
не обращается к GitHub и не перемещает указатели существующих веток.
После установки рабочая копия находится в detached HEAD.

Рабочий каталог сайта:
`/opt/legacy-stack/sites/sweb/site.urbaso.ru/public_html`.
Оба домена, `urbaso.ru` и `site.urbaso.ru`, используют этот каталог.
Старый каталог `/opt/legacy-stack/sites/sweb/urbaso.ru/public_html` не затрагивается.

## Установка из GitHub

Если проверенный релиз опубликован в `urbatron/site-urbaso`, архив загружать вручную
не требуется. Скачанная из точного целевого коммита копия
`scripts/install-performance-from-github.py` запускается вне webroot:

```bash
python3 /root/папка-установки/install-performance-from-github.py \
  --target ПОЛНЫЙ_SHA_РЕЛИЗА --baseline ПОЛНЫЙ_SHA_BASELINE
```

Ветка по умолчанию — `codex/performance-pagespeed-20261011`. Скрипт скачивает её
в отдельный каталог `/root/urbaso-performance-*` через существующий ключ
`/root/.ssh/id_ed25519_site_urbaso_repo`; проверка известного SSH-хоста обязательна.
Проверяются точный SHA ветки и четыре шага линейной истории: целевой коммит
с исправлением установщика → прежний релиз `db29fe35b793d415e5dd77e04774ab5394086c74`
→ опубликованный код `790642c73c8dec2d5fd7e72944ef97ea15dceab0`
→ baseline с Метрикой → исходный `22fc0324edce4f4fec3ecf7bc65ff75a8e823cb9`.
У каждого из четырёх новых коммитов должен быть ровно один ожидаемый родитель.
Дополнительно проверяются точные байты исходного `index.html` с Метрикой.
После этого скрипт собирает автономный bundle со всей историей релиза, без
требований к наличию коммита слияния в Git-копии VPS, и запускает тот же
установщик кода и Nginx, что описан ниже. До его проверок рабочая копия сайта
не изменяется. Резервные копии, команды отката и работа с указателями веток
одинаковы для обоих способов доставки.

## Обновление уже установленного релиза

Для следующего небольшого изменения используется отдельный режим, без повторной
настройки Nginx и без скачивания всей истории репозитория:

```bash
python3 /root/папка-установки/install-performance-from-github.py \
  --target ПОЛНЫЙ_SHA_НОВОГО_РЕЛИЗА --upgrade-from ПОЛНЫЙ_ТЕКУЩИЙ_SHA
```

Bootstrap создаёт временный bare-репозиторий, читающий имеющиеся объекты Git
рабочей копии, и получает новые объекты из проверенной рабочей ветки. Текущий
HEAD должен точно совпадать с `--upgrade-from`, а целевой коммит должен иметь
единственным родителем этот SHA. Передаётся только небольшой incremental bundle.
Ни рабочие файлы, ни указатели веток исходного репозитория на этом этапе
не изменяются. Запускается только установщик кода:

```bash
python3 /root/папка-установки/install-performance-release.py upgrade \
  /root/папка-установки/release.bundle ПОЛНЫЙ_НОВЫЙ_SHA ПОЛНЫЙ_ТЕКУЩИЙ_SHA
```

В этом режиме все отслеживаемые файлы и индекс должны быть чистыми: исключение
для старого незакоммиченного добавления Метрики не применяется. Подтверждённое
состояние `skip-worktree` проверяется и сохраняется по тем же правилам, что ниже.
Существующие резервирование, проверка публичного HTML и автоматический возврат
при ошибке действуют и для обновления. Напечатанная команда отката возвращает
непосредственно предыдущий релиз; конфигурация Nginx остаётся установленной.

## Состав архива

- `release.bundle`: объекты Git исходного состояния и проверенного релиза.
- `release.json`: полные SHA исходного коммита, baseline и релиза, контрольные суммы.
- `install-performance-release.py`: копия одноимённого скрипта релиза.
- `configure-performance.py`: отдельный установщик настроек Nginx.
- `install.py`: проверка контрольных сумм и последовательный запуск обоих шагов
  (исходник в репозитории — `scripts/install-performance.py`).
- `README.txt`: точные команды для этого архива.

Архив распаковывается вне публичного каталога сайта, например в `/root`.
Точные значения SHA передаются вместе с конкретным релизом, а не выбираются
по текущему состоянию какой-либо удалённой ветки.

## Установка кода

```bash
python3 /root/папка-релиза/install-performance-release.py install \
  /root/папка-релиза/release.bundle ПОЛНЫЙ_SHA_РЕЛИЗА ПОЛНЫЙ_SHA_BASELINE
```

Установщик проверяет:

1. Корень репозитория и `origin` проекта `urbatron/site-urbaso`.
2. Полноту bundle, существование коммитов и происхождение релиза от baseline.
3. Текущий HEAD: baseline, его единственный исходный родитель либо описанный ниже
   точный серверный коммит с тем же деревом файлов.
4. Отсутствие staged-изменений и неизвестных изменений отслеживаемых файлов.
5. Отсутствие файлов вне Git, включая игнорируемые, которые пересекаются с релизом.
6. Отсутствие незавершённой Git-операции и параллельной установки.

Разрешено только одно известное незакоммиченное изменение: `index.html` с
установленной Метрикой, побайтно совпадающий с файлом в baseline. Этот файл
сохраняется вместе с исходным состоянием. При другом содержимом установка
останавливается до изменения кода сайта.

На VPS подтверждён исходный HEAD `b08e39e019ec237ab8071cc4f6da90ad757cea15`.
Он допускается только при исходном родителе baseline `22fc0324edce4f4fec3ecf7bc65ff75a8e823cb9`
и полном совпадении деревьев обоих коммитов. Фактические SHA и ветка VPS сохраняются
для отката; эквивалентность файлов не подменяет исходную историю сервера.

Единственное допустимое специальное состояние индекса — `skip-worktree` для
неиспользуемого `assets/images/hero/code-fragment.webp`, чей режим и Git blob
должны совпадать в исходном состоянии, baseline и релизе. Файл может отсутствовать
либо содержать точные исходные байты. Другое содержимое или символическая ссылка
останавливают установку. Флаг не снимается, файл не перезаписывается; его наличие,
байты и флаг проверяются при установке и откате и записываются в сведения о копии.
Другие специальные флаги индекса по-прежнему блокируют установку.

Резервная копия создаётся в `/root/backups/site.urbaso.ru/performance-code-*`.
Она содержит исходный `index.html`, SHA, исходную ветку, контрольные суммы
и автономную копию установщика. Git-коммиты удерживаются отдельными ссылками
`refs/backups/performance-code-*/…`; обычные указатели веток не меняются.

После переключения проверяется чистота отслеживаемых файлов и побайтное
совпадение публичного `index.html` с установленным. Если установка или эта
HTTP-проверка завершатся ошибкой, скрипт попытается автоматически восстановить
исходный код. При неизвестных последующих изменениях восстановление остановится,
чтобы их не потерять. Команда ручного отката печатается до первого изменения сайта.

## Настройки сервера

Сжатие и кеширование устанавливаются отдельно скриптом
`configure-performance.py`; порядок и откат описаны в
[performance-server.md](performance-server.md).

Сначала устанавливается код, затем конфигурация. Ошибка проверки Nginx
восстанавливает прежнюю конфигурацию сервера; успешно установленный новый код
при этом остаётся. Для полного возврата нужно выполнить обе напечатанные команды
отката: сначала конфигурации, затем кода. Копии не удаляются автоматически.

## Откат кода

Использовать точную команду из вывода установщика:

```bash
python3 /root/backups/site.urbaso.ru/performance-code-ID/install-performance-release.py \
  rollback /root/backups/site.urbaso.ru/performance-code-ID
```

Откат проверяет резервную копию, текущий SHA и отсутствие новых изменений.
Возвращается исходный коммит и точный исходный `index.html` с Метрикой. Исходная
ветка выбирается только если её указатель по-прежнему находится на исходном SHA;
если ветку уже сдвинули, восстановление выполняется в detached HEAD. Ни одна
ветка принудительно не откатывается. Повторный запуск отката допустим.

После восстановления открыть оба адреса сайта и проверить основные действия.
Этот скрипт не откатывает внешние сервисы или конфигурацию Nginx.

## Изолированная проверка

Для временных Git-репозиториев предусмотрены явные параметры `--site-root`,
`--backup-root`, `--site-url`. Публичная HTTP-проверка остаётся обязательной;
для теста можно указать локальный HTTP-сервер. Скрипт, bundle и резервная копия
должны располагаться вне тестового webroot, как и при установке на VPS.

Для подтверждённого серверного HEAD проверены установка и повторный откат
с присутствующим и отсутствующим файлом `skip-worktree`, сохранение ветки и
Метрики, отказы при чужом флаге, изменённом файле, ссылке и другом SHA с тем же
деревом. Изменение наличия файла после установки блокирует откат до возврата
сохранённого состояния. Резервные копии прежнего формата также поддерживаются.
